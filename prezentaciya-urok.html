HTTP-запросы в браузере

О чём урок: как страница в браузере «спрашивает» и «отправляет» данные на сервер с помощью fetch() и четырёх типов запросов: GET, POST, PUT, DELETE.

Где смотреть примеры: в проекте — папки html/ и js/. Откройте нужный HTML в браузере (можно просто двойным щелчком по файлу или через локальный сервер — главное, чтобы был интернет).

Для тренировки используем тестовый сайт jsonplaceholder.typicode.com — он отдаёт выдуманные «посты» в виде JSON, ничего настоящего не ломает.

Зачем это в вебе

  • GET — «дай мне данные»: список постов, страница профиля и т.п.
  • POST — «создай новую запись» на сервере.
  • PUT — «замени запись целиком», например обновить пост с нужным номером (id).
  • DELETE — «удали запись» с этим номером.

Эти четыре действия по-английски называют CRUD (создать, прочитать, обновить, удалить) — это самый частый набор операций с данными в приложениях.

Связка HTML + JS

В разметке внутри <body> стоят кнопки и поля с уникальными id, а в конце страницы подключается файл со скриптом, например так:

<button id="loadData">…</button>
<div id="result"></div>
<script src="../js/GET.js"></script>
Идея: скрипт по id находит кнопку и место для текста, при нажатии на кнопку делает запрос и подставляет ответ в блок result (через innerHTML).
POST и PUT: в форме есть поля с id вроде title, body, иногда postId — скрипт читает их тем же способом: getElementById('title') и т.д.

Что такое fetch

fetch — это встроенная в браузер функция: она отправляет HTTP-запрос по адресу (URL) и получает ответ от сервера. Её не нужно подключать библиотекой — она уже есть в современном JavaScript.

  • Самый простой вызов — один аргумент, адрес страницы API. Так по умолчанию уходит запрос GET: «дай данные по этому URL».
  • Второй аргумент — объект настроек: там указывают method ('POST', 'PUT', 'DELETE'), при необходимости headers (например, что тело — JSON) и body — строку с данными, которую сервер должен прочитать.
  • Результат не приходит сразу: fetch возвращает обещание (Promise). Когда ответ придёт из сети, дальше подключаются .then и .catch — или тот же смысл через await (см. следующий слайд).
  • Объект ответа — это не сами «данные поста» сразу: часто сначала проверяют успешность (response.ok), а данные в формате JSON забирают вызовом response.json() (он тоже асинхронный, поэтому его обычно ставят внутрь .then).
// GET — только адрес
fetch('https://пример.com/api/posts');

// POST — адрес + настройки и тело
fetch('https://пример.com/api/posts', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Заголовок', body: 'Текст' })
});

Дальше в презентации тот же fetch повторяется в каждом файле — меняется только метод и то, что передаём в запросе.

Как ждать ответ: .then / .catch и await

fetch и response.json() не «возвращают данные мгновенно»: они возвращают Promise — объект «когда-нибудь будет результат или ошибка». С этим работают двумя привычными способами.

  • Цепочка .then: в каждый .then передают функцию; она вызовется, когда предыдущий шаг завершится. То, что вы вернули из функции (в том числе новый Promise от json()), становится входом для следующего .then. .catch подписан на сбой в любой точке цепочки (сеть, неуспешный HTTP-код после throw, ошибка парсинга).
  • async / await: функция помечается как async; перед Promise пишут await — выполнение функции приостанавливается до результата, дальше код читается сверху вниз. Ошибки из await и из обычного кода ловят в try { … } catch (e) { … } — по смыслу это тот же .catch, только рядом с кодом.

Один и тот же сценарий «получить JSON после GET» — два эквивалентных стиля (в проекте используется первый):

// 1) then — как в GET.js / POST.js / PUT.js
fetch(url)
  .then(response => { if (!response.ok) throw new Error(response.status); return response.json(); })
  .then(data => { /* работа с data */ })
  .catch(err => { /* показать ошибку */ });

// 2) await — тот же поток, другой синтаксис
async function load() {
  try {
    const response = await fetch(url);
    if (!response.ok) throw new Error(response.status);
    const data = await response.json();
    /* работа с data */
  } catch (err) { /* показать ошибку */ }
}

Важно в контексте: после fetch у вас ещё нет тела ответа как объекта — сначала объект Response (ok, status), затем отдельный шаг json(), который тоже асинхронный, поэтому его либо ставят во второй .then, либо пишут вторым await.

GET.js — полный код

const btn = document.getElementById('loadData');
const result = document.getElementById('result');


btn.addEventListener('click', () => {
  result.innerHTML = 'Загрузка... ⏳';


  fetch('https://jsonplaceholder.typicode.com/posts')
    .then(response => {
      if (!response.ok) {
        throw new Error('Ошибка запроса: ' + response.status);
      }

      return response.json();
    })
    .then(data => {

      const firstFive = data.slice(0, 5);
      result.innerHTML = `<h3>Полученные данные:</h3><pre>${JSON.stringify(firstFive, null, 2)}</pre>`;
    })
    .catch(error => {
      result.innerHTML = `<span style="color:red;">${error.message}</span>`;
    });
});

В контексте интерфейса: addEventListener('click', …) запускает всю цепочку только по клику; пока запрос идёт, в блок результата сразу пишут текст загрузки.

fetch с одним URL: по умолчанию это GET — запрос списка постов; возвращается Promise с объектом ответа, не сразу массив данных.

Первый .then: проверка response.ok отсекает «плохие» HTTP-коды; при успехе return response.json() передаёт в следующий шаг уже Promise с распарсенным массивом.

Второй .then: работа с данными — slice(0, 5) и вывод через innerHTML с JSON.stringify для читаемого вида.

.catch: единая точка для сетевых сбоев, ответа не-JSON и ошибок, выброшенных через throw в предыдущем then.

POST.js — полный код

const sendBtn = document.getElementById('sendBtn');
const result = document.getElementById('result');

sendBtn.addEventListener('click', () => {
    const title = document.getElementById('title').value;
    const body = document.getElementById('body').value;

    // Проверяем, что поля не пустые
    if (!title || !body) {
        result.innerHTML = '<span style="color:red;">Пожалуйста, заполните все поля</span>';
        return;
    }

    result.innerHTML = 'Отправляем данные... ⏳';


   fetch('https://jsonplaceholder.typicode.com/posts', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      title: title,
      body: body,
      userId: 1
    })
  })
  .then(response => {
    if (!response.ok) {
      throw new Error('Ошибка запроса: ' + response.status);
    }
    return response.json();
  })
  .then(data => {
    result.innerHTML = `<h3>Ответ сервера:</h3><pre>${JSON.stringify(data, null, 2)}</pre>`;
  })
  .catch(error => {
    result.innerHTML = `<span style="color:red;">${error.message}</span>`;
  });
});

Перед fetch: из полей ввода читают .value; пустые поля обрабатывают локально (return), чтобы не слать бессмысленный запрос.

Второй аргумент fetch: method: 'POST'; headers['Content-Type'] сообщает серверу, что тело — JSON; body должен быть строкой, поэтому объект собирают через JSON.stringify (включая userId, как ожидает JSONPlaceholder).

Цепочка then / catch: та же схема, что в GET — сначала проверка ответа и response.json(), затем вывод объекта «созданного» поста (часто с новым id); сбои попадают в catch.

PUT.js — полный код

const updateBtn = document.getElementById('updateBtn');
const result = document.getElementById('result');

updateBtn.addEventListener('click', () => {
  const postId = document.getElementById('postId').value;
  const title = document.getElementById('title').value;
  const body = document.getElementById('body').value;

  if (!postId || !title || !body) {
    result.innerHTML = '<span style="color:red;">Заполните все поля</span>';
    return;
  }

  result.innerHTML = 'Отправляем запрос... ⏳';

  fetch(`https://jsonplaceholder.typicode.com/posts/${postId}`, {
    method: 'PUT',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      id: postId,
      title: title,
      body: body,
      userId: 1
    })
  })
  .then(response => {
    if (!response.ok) throw new Error(`Ошибка: ${response.status}`);
    return response.json();
  })
  .then(data => {
    result.innerHTML = `
      <h3>Ответ сервера:</h3>
      <pre>${JSON.stringify(data, null, 2)}</pre>
    `;
  })
  .catch(error => {
    result.innerHTML = `<span style="color:red;">${error.message}</span>`;
  });
});

URL с подстановкой: шаблонная строка с ${postId} указывает ресурс «пост с таким id»; метод 'PUT' вместе с телом JSON означает «замени представление этого ресурса».

Тело запроса: снова JSON.stringify объекта с id, обновлёнными title / body и userId — сервер сопоставляет путь и тело по правилам API.

Обработка ответа: как в POST — ok → json() → второй then для отображения; ошибки HTTP — через throw в общий catch.

DELETE.js — полный код

const deleteBtn = document.getElementById('deleteBtn');
const result = document.getElementById('result');

deleteBtn.addEventListener('click', () => {
  const postId = document.getElementById('postId').value;

  if (!postId) {
    result.innerHTML = '<span style="color:red;">Введите ID поста</span>';
    return;
  }

  result.innerHTML = 'Отправляем запрос на удаление... ⏳';

  fetch(`https://jsonplaceholder.typicode.com/posts/${postId}`, {
    method: 'DELETE'
  })
    .then(response => {
      if (response.ok) {
        result.innerHTML = `<span style="color:green;">Пост с ID ${postId} успешно удалён ✅</span>`;
      } else {
        throw new Error(`Ошибка: ${response.status}`);
      }
    })
    .catch(error => {
      result.innerHTML = `<span style="color:red;">${error.message}</span>`;
    });
});

fetch с method: 'DELETE': достаточно адреса с id в пути; тело запроса обычно не передают.

Первый then без json(): для DELETE ответ часто без полезного JSON — проверяют только response.ok и по веткам показывают успех или throw для кода ошибки.

catch: как и в других примерах — ловит сеть, исключения из then и показывает сообщение пользователю.

Что показать ученикам на практике

  1. Открыть html/GET.html, нажать кнопку — на экране появится кусок JSON со списком постов.
  2. POST — ввести заголовок и текст, отправить — в ответе будет «новый» пост с номером (на тестовом сайте это условность, не настоящая база).
  3. PUT — указать, например, номер 1, поменять текст — в ответе увидите обновлённые поля.
  4. DELETE — снова номер 1 — появится сообщение об успехе (на демо-сервере ничего реально из базы не стирается).
